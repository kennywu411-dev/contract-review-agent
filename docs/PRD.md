# PRD：采购合同审查，把每条风险算成钱

标【假设】的是还没有用真实用户验证过的判断，验证方案见 [用户试用方案](用户试用方案.md)。评测数字都来自构造数据，出处见 [numbers.md](numbers.md)。

## 1. 一句话

签采购合同之前，帮没有专职法务的采购人员把对我方不利的条款找出来，说清楚为什么不利、依据是哪条法律或公司规定、应该怎么改，并把每条能算的风险换算成金额：这份合同不改，最坏多花多少钱，先谈哪一条。拿不准的交给法务，算不了的不硬算。

主打场景是采购合同（我方是付款方）。其他合同类型和我方是收款方的情况照常审查，能算的金额照算。

## 2. 要解决的问题

很多中小企业没有专职法务，采购、行政和业务负责人看合同主要靠经验和对方提供的模板【假设】。常见的坑是固定的几类：违约金只约束一方、检验期过短且逾期视为合格、背靠背付款、对方可以随时解除、管辖地在对方所在地、定金超过 20% 等。这些条款单看都不起眼，签了之后出问题才发现。

只给"高 / 中 / 低"还不够。采购拿到十条意见，谈判时间只够谈两三条，需要知道哪条最值钱【假设】；向领导汇报时，"第九条违约金不对等，逾期一个月我方比对方多赔 6.9 万元"比"第九条高风险"更容易得到支持【假设】。

现有的做法各有问题：

- 请外部律师逐份审：贵、慢，几万元以下的小合同不值得【假设】。
- 直接把合同贴进通用聊天机器人：会给意见，但不站在我方立场，引用的法条可能是编的，也不知道公司自己的审批规定。
- 公司内部审查规范：多数写成文件放在那里，业务人员签合同时不会逐条去对【假设】。
- 让通用模型直接估金额：算式看不到，同一份合同问两次可能得到两个数，算错了也没有提示（对照实验见第 7 节）。

## 3. 目标用户

| 用户 | 场景 | 最在意的 |
|---|---|---|
| 主要：中小企业的采购人员和采购负责人（无专职法务） | 签采购合同前自己先过一遍，决定先找对方改哪几条、要不要报给领导或外部律师 | 快、看得懂、改法能直接用、知道每条值多少钱 |
| 次要：行政、业务负责人 | 签销售、委托、数据类合同前先过一遍 | 同上；金额只在能算时给 |
| 次要：企业法务 | 合同量大时先让系统做初筛，自己只看高风险和系统拿不准的部分 | 不漏报、依据可查、能对照公司规范 |

不针对：律师事务所的专业审查、个人消费类合同（租房、劳动合同等可以作为试用的补充场景，但不是产品重点）。

## 4. 核心流程

1. 选择公司（租户）后上传或粘贴合同。
2. 系统判断我方是甲方还是乙方；合同里看不出来时先反问，不猜。
3. 逐条输出意见：条款位置、风险类型、高/中/低等级、理由、可以直接替换的修改建议、依据编号。
4. 点依据编号可以看到法条或公司规范的原文高亮。
5. 依据核实不了的意见不删除，标"转法务复核"。
6. 金额测算和审查同时进行：系统把合同里的数字（总额、每行标的的单价和数量、预付款、账期、定金、违约金、质保金）抄出来，逐个核对原文，查供应商台账的历史均价，按公式算出每项金额。
7. 每条意见上显示"这条不改，最坏多花多少钱"，点开看算式、用到的合同原文和假设；算不了的写明原因。
8. 汇总区显示最坏情况合计（分成"不改就确定多花"和"最坏情景下的敞口"）和按金额排序的谈判优先级。没被报成风险、但确实多花钱的条款（例如账期比公司标准短）也列在这里。
9. 可以继续追问："第 3 条怎么改""换成乙方视角再看一遍"。

## 5. 范围

做：

- 7 类常见商业合同：工业品买卖、农产品买卖、加工承揽、仓储委托、数据委托处理、数据产品开发、数据供应。
- 11 类风险：违约金过高或不对等、免责与责任限制、单方解除、检验期过短、付款条件不利、保密缺失或不对等、知识产权归属不利、管辖不利、自动续约、定金超过 20%、单价高于台账均价。
- 依据来源：《民法典》、合同编通则解释、《民事诉讼法》、官方合同示范文本、公司自己的审查规范。
- 金额测算 5 项（公式见 [ADR 014](adr/014-金额测算.md)）：
  - 比价：单价高于台账均价且超过公司标准时，本单多付多少，多行标的逐行算；
  - 付款条件的资金占用成本：预付款、定金、账期相对公司标准付款条件多占用的资金成本；
  - 违约金：同样逾期 30 天，我方比对方多付多少；超出公司上限多少；
  - 定金超过法定 20% 的部分；
  - 质保金低于公司标准的缺口（我方收款时算被占用的资金成本）。
- 每个金额带算式、合同原文位置和假设。资金成本率、情景天数、公司标准条件是每家公司一份的配置。

不做：

- 不出具法律意见，不替代律师和法务的最终判断。
- 不做合同起草、电子签署、合同台账管理和履约提醒。
- 不给没有确定数字的风险估金额：单方解除、检验期、管辖、保密、知识产权、自动续约、责任限制，以及背靠背付款、以实际损失为基数的违约金。这些标"无法量化"并说明原因。
- 不预测违约概率，不做期望损失。"最坏情景"是一个写明的假设（双方各逾期 30 天），不是预测。
- 不审诉讼、仲裁文书，不做建设工程等专业领域合同。
- 当前版本只为本机演示设计，没有登录和权限体系，不对外部署。

## 6. 指标

| 层级 | 指标 | 定义 | 当前值（构造数据） | 目标 |
|---|---|---|---|---|
| 北极星 | 每份合同被采纳的高/中风险意见数 | 用户标"有用"或照着修改建议改了的意见数 | 无，需要试用 | 试用后定基线 |
| 离线 | 风险检出率 | 植入的风险里被报出来的比例 | v1 100%；v2 难评测集 100%（75/75，两次） | 不低于 95% |
| 离线 | 意见精确率（高/中） | 报出的高/中意见里确实是风险的比例 | v1 82.3%；v2 62.6–65.7% | v2 提到 75% |
| 离线 | 依据引用准确率 | 引用落在该风险合法依据集合里的比例 | v1 100% | 不低于 95% |
| 离线 | 金额正确率 | 应有金额的测算项里，系统给出金额且误差 ≤ 1% 的比例 | 留出集 100% 和 99.2%（133 项，两次） | 不低于 98% |
| 离线 | 字段抽取准确率 | 合同里应抄出的数字，被抄出、通过原文核对且数值相同的比例 | 留出集 99.4% 和 100%（641 个） | 不低于 98% |
| 离线 | "无法量化"判断 | 算不了的条款被标成无法量化、没有硬给金额的比例 | 留出集 26/26，两次 | 100% |
| 在线 | 意见采纳率 | 被标"有用"的意见 ÷ 全部意见 | 无 | 试用后定基线 |
| 在线 | 误报反馈率 | 被标"没用 / 不是风险"的意见 ÷ 全部意见 | 无 | 试用后定基线 |
| 在线 | 金额被用于谈判的比例 | 用户照着优先级去谈、或把金额写进汇报的合同占比 | 无 | 试用后定基线 |
| 在线 | 审完一份合同的时间 | 从上传到看完全部意见 | 系统耗时 P50 约 28 秒 | 用户总耗时比自己看短一半【假设】 |
| 护栏 | 漏报 | 法务抽检发现、系统没报的高风险 | v2 构造数据为 0 | 试用中每一例都复盘 |

## 7. 关键取舍

| 问题 | 选择 | 依据 |
|---|---|---|
| 漏报和误报哪个更重要 | 优先不漏报 | 漏掉一个高风险条款的代价远大于多看一条误报。v2 上改进后的多 Agent 检出 100%，代价是误报回升、成本约 1.75 倍，接受 |
| 单 Agent 还是多 Agent | 首轮审查用多 Agent，追问用单 Agent | v1 上干净合同的误报意见从 13–14 条降到 4–6 条，检出持平（ADR 012） |
| 依据核实不了的意见怎么办 | 不删除，标转法务复核 | 删掉会造成漏报；标出来让人决定。无依据且未标转人工的意见从 6.6% 降到 0.8%（ADR 008） |
| 看不出我方立场怎么办 | 先反问 | 立场判断错了，整份意见都会反过来。当事人空白的合同反问率 100%，多余反问 0% |
| 公司规范怎么用 | 每家公司只能检索到自己的规范，台账也只能查到自己的数据 | 不同公司的红线不同，混在一起会给出错误的依据（问题日志 P21 修复过一次跨租户读数据的漏洞） |
| 金额谁来算 | 模型只抄数字，金额由规则代码算 | 留出集上两种做法的准确率没有显著差别（规则 100% / 99.2%，模型直接算 97.0%–99.2%）。选规则的理由是另外三点：给出的金额分毫不差（直接算只有 77%–81%）；同一份合同跑两次，300 项里 299 项结论完全一样（直接算 271–274 项）；出错时是"不给金额"，直接算出错时是差 10 倍的金额且没有提示。另外更便宜（$0.00053 比 $0.00073–0.00087）、更快（2.6 秒比 4.5–5.4 秒）（ADR 014） |
| 抄错了怎么办 | 每个数字核对原文，核对不上不出金额 | 错的金额比没有金额危害大：采购会拿着它去谈判 |
| 算不了的怎么办 | 标"无法量化"并写原因，不估 | 背靠背付款、按实际损失计的违约金没有确定的数，估出来的数没有依据 |
| 假设放在哪 | 每家公司一份配置，每个金额旁边列出用到的假设 | 资金成本率、逾期天数各家不同；不写明就成了"系统说的数" |
| 用哪个模型 | 默认 Haiku，DeepSeek 作为私有化备选 | DeepSeek 检出持平，但精确率低约 6 个点，花费约 2.4 倍（ADR 010） |
| 场景为什么从高校问答改成合同审查 | 换场景 | 方法在问答场景里验证过，但问答类产品辨识度低，合同审查是企业实际要花钱解决的问题（ADR 007） |

## 8. 风险

- 法律责任：输出必须明确"不构成法律意见"，高风险意见建议找法务或律师确认。
- 数据安全：合同里有价格、客户、商业条款。企业版需要私有化部署或不留存合同原文；当前演示只在本机运行。
- 过度依赖：用户可能只看系统列出来的问题，忽略系统没覆盖的风险。界面上要写清楚覆盖的合同类型和风险类型。
- 构造数据的偏差：评测集是自己构造的，真实合同的写法更多样，线上效果可能明显低于离线数字。试用是为了尽早发现这个差距。
- 法规更新：法条和示范文本以入库时的版本为准，需要定期更新。
- 金额被当成精确预测：金额是按写明的假设算出来的测算值。界面上分开显示"确定多花"和"最坏情景敞口"，并列出假设；仍然可能被直接引用成"会损失这么多"。
- 金额测算只在构造合同上评测过：v3 的条款写法是生成器的几种模板，真实合同的写法更多（阶梯价、分期付款、外币、含税和不含税混写），抄数和核对规则都可能不适用，这时应当表现为"需人工核对"而不是给错金额，需要用真实合同验证。

## 9. 商业模式【假设】

- 成本：单份合同的模型花费在 1 美分左右，主要成本在获客和私有化部署的实施。
- 收费方式的候选：按份计费（适合合同量小的公司）；按席位订阅，包含公司规范配置（适合有一定合同量的公司）；私有化部署按年收费（适合对数据敏感的企业）。
- 差异点：依据可以点开看原文、能接入公司自己的审查规范和供应商台账、拿不准的会明确交给法务。这几点是否值得付费，需要试用和访谈验证。

## 10. 待验证的假设

1. 目标用户确实会在签合同前主动用一个工具先过一遍，而不是只在出问题后才找人。
2. 用户看得懂风险理由，并且愿意直接用系统给的修改建议去和对方谈。
3. 真实合同上的误报率用户能接受，不会因为意见太多而放弃使用。
4. "依据原文可点开"和"接入公司规范"是用户在意的差异点。
5. 审完一份合同的总时间明显比自己看要短。
6. 采购确实会按金额排序去谈判，金额让意见更容易被领导和对方接受。
7. "资金占用成本"这类不违规但多花钱的条款，用户愿意看到，而不是觉得多余。
8. 30 天逾期情景和各家的资金成本率，用户愿意自己配置，或者接受默认值。

验证方法见 [用户试用方案](用户试用方案.md)。
