# PRD：高校规章问答助手（早期场景，已改为合同风险审查，见 ADR 007）

> 版本 v0.2（阶段 0）。标【假设】的是尚未验证的判断；标的是实施时定下的约定，可以推翻。
> 本项目不招募真实用户：评测题来自公开渠道里学生真实提过的问题，以及学校官方 FAQ（见第 7 节），所有结论都基于离线评测。

## 1. 一句话

学生用中文问学校规章，比如转专业、推免、奖学金、学分、缓考、学位授予。agent 从本校和国家层面的正式文件里找答案，逐句标出处（文件 + 页码），点开能跳到原文高亮；需要查数字时去查结构化表（由 DataPilot 提供）；信息不够就先反问；文件里没有就明确拒答。

## 2. 为什么做

用户侧【假设，依据是公开渠道里的学生提问】
- 规章分散在教务处、学工处、研究生院等多个网站，PDF 版本多，新旧混杂。
- 学生的实际做法是问辅导员、在年级群问学长学姐，得到的答案经常互相矛盾，或者已经过时。
- 在推免、奖学金、毕业审核这些节点上，理解错一条规定就会错过机会。

求职侧（项目定位）
- DataPilot 已经证明了"结构化数据 + agent"（NL2SQL），DocPilot 补上"非结构化文档 + agent"。两者合起来就是一个故事：文档和表格，由同一个 agent 来调度。
- 与 DataPilot 的区别：DataPilot 用的是公开基准 BIRD；DocPilot 用真实的学校文件，题目来自真实的学生提问，还有一个"跨校隔离"的多租户问题。

## 3. 目标用户（画像，不招募）

| 项 | 内容 |
|---|---|
| 用户 | 在校本科生，每人只关心自己学校 |
| 覆盖学校 | 南京理工大学、中国石油大学（华东）、兰州大学、中国矿业大学、郑州大学、北京师范大学 |
| 高频问题域【假设】 | 转专业、推免/保研、奖学金与助学金、学分与毕业要求、请假/缓考/重修、学籍异动（休学、退学）、学位授予、违纪处分 |
| 现有替代方案 | 翻官网 PDF、问辅导员、年级群、学长学姐、小红书/知乎/贴吧经验帖 |

## 4. 核心场景

| # | 场景 | 示例问题 | agent 行为 |
|---|---|---|---|
| S1 | 纯文档问答 | "缓考怎么申请，截止时间是什么？" | 检索本校和通用层 → 逐句带出处回答 |
| S2 | 文档 + 查表 | "国奖要什么条件，能拿多少钱？" | 条件查文档；金额、名额通过 DataPilot 查表；合并回答，两类出处都标 |
| S3 | 反问澄清 | "我还差多少学分毕业？" | 缺专业和年级 → 先反问 → 拿到后查学分要求表；不读个人成绩，只告诉学生要求和计算方法 |
| S4 | 拒答 | "食堂几点关门？" | 文件里没有 → "现有学校文件中没有相关规定，建议咨询后勤处"，不编造 |
| S5 | 本校与国家规定并存 | "休学最长可以几年？" | 两条都列出并注明"以本校规定为准"；冲突处标出 |
| S6 | 防跨校串答 | 北师大学生问推免条件 | 只用北师大和通用层的文件；不得引用其他学校的条款 |

## 5. 数据范围

两层文档 + 一层表格

| 层 | 内容 | 规模估计 |
|---|---|---|
| 通用层（全员共享） | 教育部《普通高等学校学生管理规定》（第 41 号令）、《学位法》（2024）、国家奖学金/国家励志奖学金/国家助学金相关管理办法等 | 8–10 份 |
| 学校层（每校精简包） | 学生手册、学籍管理、推免办法、奖学金评定、学士学位授予、转专业，每校 5–8 份 | 6 校 × 5–8 份 ≈ 30–50 份 |
| 结构化表（SQLite，交给 DataPilot 查） | 通用表：国家奖助学金标准；每校表：奖学金种类/金额/名额；2 所深度校另加学分要求和校历关键日期。所有表都带 `school` 列 | 10–20 张表 |

- 文档总量预计 40–60 份、约 1200–2000 页（两本深度校学生手册就有 652 页）。各校可得性和全部 URL 见 [校园文件调研.md](校园文件调研.md)。
- 深度校：北京师范大学 + 中国石油大学（华东）【依据调研】
  - 两校都有本科生整本学生手册，是新版文字版 PDF（北师大 2025 版 378 页，中石油 2025 版 274 页），覆盖了学籍、转专业、学位、奖学金。
  - 中石油还有 2024/2025/2026 三版手册和 13 个学年的校历，适合做"版本/年级陷阱"题。
  - 中石油没有校级推免办法，推免题按拒答处理，或只用学院细则并注明。
  - 备选深度校：中国矿业大学（单行本最齐全，全是文字版 PDF，但多为 2021 版）。
- 其余 4 校的已知缺口：
  - 郑州大学：学籍管理规定只找到 2017 版，学位细则 2025 版找不到原文。
  - 兰州大学：没有整本学生手册。
  - 南京理工大学：推免办法已失效。
  - 这些缺口如实入库并作为拒答题素材，不去找非官方来源补。
- 通用层以现行文号为准：
  - 《学生资助资金管理办法》用财教〔2021〕310 号，它取代了财科教〔2019〕19 号；
  - 国家奖学金和国家励志奖学金的金额以财教〔2024〕181 号为准（本专科国奖 1 万元，励志 6000 元）。
  - 通用层多为网页，出处用"文件名 + 条款号"代替页码。
- 采集方式：南京理工大学和兰州大学的网站有反爬，中石油部分页面限校内访问。阶段 1 用浏览器手动下载，只收公开可访问的文件，并记录每份文件的 URL 和下载日期。
- 每份文档记录元数据：学校、文件名、发文单位、发布或修订日期、适用年级（如有）、原始 URL、下载日期。
- 只用官网公开文件；需要校内登录才能拿到的文件不收。

## 6. 非目标（明确不做）

- 不招募真实用户，不做线上试用和用户访谈。
- 不接教务系统，不读个人成绩和学籍数据，不代办任何申请。
- 不做个案裁决（例如"我这种情况会不会被处分"），只给条文和办事渠道。
- 不覆盖 6 所以外的学校；v1 只收本科文件，研究生问题按拒答处理。
- 不做多轮闲聊、选课推荐这类非规章问题（按 S4 拒答）。
- 不做公网部署、账号体系、文件自动更新爬虫；本地运行，一条命令复现。
- 界面声明："回答依据已收录的学校公开文件，以学校最新正式通知为准。"

反目标（技术上能用，但算失败）
- 张冠李戴：把 A 校的规定当成 B 校的回答。
- 引用对不上：出处标得很漂亮，原文里却没有这句话。
- 为了显得有用，拒答率压得很低，结果编造内容。
- 评测集"自己出题自己考"：题目照着文件原句改写，导致召回率虚高（第 7.1 节专门防范）。

## 7. 评测集与指标

### 7.1 评测集怎么来

| 来源 | 说明 | 占比目标 |
|---|---|---|
| 学校官方 FAQ | 教务处、学工处公开的"常见问题解答"，是真实的提问加官方答案，最适合做标准答案 | 尽量多 |
| 公开渠道的真实提问 | 知乎、贴吧、小红书等公开帖子里学生提过的问题，只取问题本身并改写为一句话，不保存帖子内容和用户信息 | 与 FAQ 合计 ≥50% |
| 按文件出题 | 由 Claude 起草，覆盖"需查表""该拒答""跨校陷阱""版本/年级陷阱"等真实来源难覆盖的类别。出题时只看文件标题和目录，不看正文，避免照抄原句 | 其余 |

- 规模 ≥100 题，分三类：可回答、需查表、该拒答；另设"跨校陷阱"子类。每题标注来源类型，看板上可以按来源拆开看，核对"自己出的题"是否明显更容易。
- 标准答案的标注：由 Claude 起草每题的类别和标准出处（文件 + 页码），作者抽查至少 20%，有争议的题剔除或记入问题日志。

### 7.2 指标

| 层 | 指标 | 定义 | 目标 |
|---|---|---|---|
| 北极星 | 问题解决率（离线） | 可回答题和需查表题中，答案正确且出处正确的比例；该拒答题中，正确拒答的比例；两者合计 | 基线在 阶段 4 后测得，阶段 7 迭代后提升 ≥10 个百分点【假设】 |
| 过程 | 检索 Recall@5 | 标准出处出现在前 5 个检索结果中的比例 | ≥85% |
| 过程 | 引用准确率 | 引用的原文确实支撑这句话 | ≥90% |
| 过程 | 拒答正确率 | 该拒答题中拒答的比例；同时报告误拒率（可回答题被拒答的比例） | ≥90%；误拒率 ≤10% |
| 过程 | 路由正确率 | 需查表题调用了查表工具、纯文档题没有多余调用的比例 | ≥85%【假设】 |
| 过程 | 反问正确率 | 缺关键信息的题先反问的比例 | 只观察 |
| 护栏 | 幻觉率 | 至少一句话没有出处支撑、或出处与原文不符的回答所占比例 | ≤5% |
| 护栏 | 跨校串答率 | 引用了非本校、非通用层文件的回答所占比例 | ≤2% |
| 护栏 | 单次成本 | 每题的 API 花费（美元） | P95 ≤ $0.01 |
| 护栏 | 延迟 | 本机从提问到答案完成 | P50 ≤ 10s，P95 ≤ 15s（阶段 3 实测后由 6s 校准，见 ADR 003） |

- 判分：答案正确性和引用准确率由 LLM 判分，再人工抽检 30 题，校准判分器，并把一致率写进看板。
- 阈值在 阶段 2 基线跑出来后可以调，调整时告知并写进问题日志。

## 8. 方案要点

- 解析：MinerU 或 docling，保留表格、标题层级、页码。阶段 1 两者都在 2–3 份真实文件上试，选一个。
- 检索：本地 bge-m3 向量 + BM25 混合，再加本地重排；先按 `school ∈ {本校, 通用}` 过滤；切块策略做对比实验。
- Agent：三类工具，即文档检索、DataPilot 只读 SQL（通过 MCP）、反问澄清；设最大步数上限，并记录完整 trace。
- 可信：生成后自动逐句校验引用，校验失败降级为拒答。
- 集成：DocPilot 自己也提供 MCP server，可以和 DataPilot 一起挂进 Claude。
- 界面：选学校、问答、可点击的引用卡片（跳原文高亮）、可展开的 agent trace、点赞/点踩（本地演示用）。
- 版本：只收现行版本；文件写明适用年级的条款，回答时注明并反问年级；评测集加入少量"版本/年级陷阱"题。
- 结构化表只用公开数据：不造示意数据；没公开的数（如学院名额）明确告知"未公开"。

### 成本估算（价格来自官方价目表）

| 模型 | 输入 / 输出 $/百万 token |
|---|---|
| Claude Haiku 5.5（`claude-haiku-5-5`，提示 ≤100K token） | $0.10 / $0.50 |
| Claude Sonnet 5.5（`claude-sonnet-5-5`） | $2.00 / $10.00（缓存读取 $0.20） |

- 粗估每题约 3 次调用、共约 25K 输入 token 和 1.5K 输出 token：Haiku 约 $0.003/题，Sonnet 约 $0.065/题。
- 100 题评测全量跑一次：Haiku 约 $0.3，Sonnet 约 $6.5；LLM 判分另计，同一量级。
- 总预算 ≤ $40：默认用 Haiku 并开 prompt caching；Sonnet 只在对比实验中使用，先跑 20 题小样本。

## 9. 竞品对比

| 维度 | RAGFlow | Dify | 飞书知识库 AI 问答 | DocPilot |
|---|---|---|---|---|
| 定位 | 开源 RAG 引擎，强在深度文档解析 | 开源 LLM 应用平台，拖拽搭工作流和知识库 | 企业协同套件里的知识问答 | 面向单一垂直场景（高校规章）的可信问答 agent |
| 文档解析 | 强（版面、表格识别） | 中（通用切分） | 依赖飞书文档格式 | MinerU/docling，保留页码和表格，做切块对比实验 |
| 结构化数据 | 弱 | 可接工具或数据库，但需要自己搭 | 多维表格，生态内可用 | 通过 MCP 调用 DataPilot，agent 自主选择查文档还是查表 |
| 引用可信 | 有引用展示 | 有引用展示 | 有来源链接 | 逐句出处 + 生成后自动校验，校验失败就拒答 |
| 评测 | 无内置离线评测 | 有基础标注和日志 | 不对外 | 内置评测集、看板、逐题 trace 回放、成本延迟面板 |
| 多租户隔离 | 按知识库隔离 | 按应用或知识库隔离 | 按企业权限隔离 | 按学校过滤，并把跨校串答作为单独指标 |
| 上手成本 | 需部署，配置项多 | 低代码，但调优依赖平台能力 | 需在飞书生态内使用 | 一条命令复现；不面向非技术用户自助搭建 |

差异化结论：DocPilot 不和平台比功能广度，而是在一个垂直场景里，把"答案可信、可核对、可评测"做深。为什么不直接用 Dify？因为评测、引用校验和路由策略需要白盒控制。（以上竞品能力描述基于公开资料，阶段 6 写讲义前会再核实一遍。）

## 10. 商业化思考（一页）【整体为假设】

- 谁付钱：高校的学工处、教务处、研究生院（采购"迎新与政策咨询助手"），或者智慧校园服务商（作为模块集成进他们已有的校园 App 或公众号）。学生端免费。
- 替代了什么：辅导员和教务老师回答重复问题的时间。每到迎新、推免、奖学金评定、毕业审核这些节点，咨询量会集中爆发。
- 单位经济（示意）：一所 2 万人的学校，每学期每人问 10 题，共 20 万题；按 Haiku 约 $0.003/题算，大约 $600/学期的模型成本。主要成本在文件整理、更新和运维，不在模型。
- 定价思路：按校年费（数万元量级），包含文件入库、每学期规章更新、咨询热点报表（"本学期学生最常问什么、哪里没答上"，这份报表对管理方价值最大）。
- 风险：
  - 高校采购周期长、决策链复杂；
  - 文件更新不及时会导致错答，责任边界需要写进协议；
  - 学生隐私与数据合规。
- 下一步验证（本项目不做）：找 1 所学校的辅导员或学生会试点，测线上的问题解决率和咨询量下降幅度。作为"如果继续做，怎么验证"来讲。
