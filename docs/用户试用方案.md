# 用户试用方案

目标：用 5–10 个真实用户、一周时间，验证 [PRD](PRD.md) 第 10 节的几条假设，并拿到第一批线上指标（采纳率、误报反馈率、审完一份合同的时间）。评测集是自己构造的，这一步是为了看清真实合同上的效果和离线数字差多少。

## 1. 招募谁

| 类型 | 人数 | 找谁 | 想验证什么 |
|---|---|---|---|
| 主要用户 | 3–5 | 中小企业的采购、行政、业务负责人，平时自己看合同、公司没有专职法务 | 会不会用、看不看得懂、建议能不能直接用 |
| 专业对照 | 1–2 | 企业法务或律师 | 意见对不对、有没有漏报、依据是否站得住 |
| 补充场景 | 1–3 | 手里有租房、劳动、外包合同的同学或朋友 | 非商业合同上的表现（不是产品重点，只看边界） |

招募消息模板：

> 我在做一个合同风险审查的小工具：上传合同，它会站在你这一方列出不利的条款、理由、改法，以及对应的法条原文。想请你花一周、审 2–3 份你手里的合同试试，每份大概 10 分钟，最后填一个简短的反馈表。合同里的公司名、金额、个人信息可以先打码。

## 2. 准备

- 访问方式：服务在本机运行，通过加了访问口令的内网穿透给试用者一个临时地址，试用结束后关闭。
- 数据告知：试用前说明合同内容会发送给模型服务商用于生成意见、不会公开、试用结束后删除本地记录；建议试用者先对公司名、金额和个人信息打码。只有同意的人参加。
- 合同来源：优先用试用者手里真实的合同；没有合适的，就用官方示范文本改写后的版本。
- 公司规范：主要用户如果所在公司有书面审查规范，可以一起导入；没有就只用通用法规。

## 3. 流程

| 时间 | 做什么 |
|---|---|
| 开始前 | 10 分钟远程演示，说明能做什么、不能做什么（不构成法律意见） |
| 试用期一周 | 每人审 2–3 份合同；每审完一份，填一次单份反馈 |
| 结束后 | 填总体问卷；挑 3–4 人做 20 分钟访谈 |
| 专业对照 | 法务或律师对同一批合同独立审一遍，作为漏报和误报的参照 |

## 4. 收集什么

单份反馈（每审完一份填一次）：

1. 合同类型、页数。
2. 这份合同你自己看大概要多久；用这个工具从上传到看完用了多久。
3. 对每条意见点审查页上的按钮打标：有用 / 没用 / 不是风险 / 看不懂。打标会自动记录（只记标签和意见的条款、类型、等级，不记合同原文），可以改标，以最后一次为准。
4. 有没有你知道是风险、但系统没报出来的条款？是哪条？
5. 修改建议有没有直接拿去用？

总体问卷：

1. 下次签合同前还会不会用（会 / 看情况 / 不会），为什么。
2. 最有用的一个点、最让你不想用的一个点。
3. "能点开看法条原文"对你有没有用。
4. 如果要收费，你能接受哪种方式：按份、按月、公司买断，或者都不接受。

访谈提纲：你平时签合同前是怎么看的；上次吃过合同的亏是什么情况；这个工具哪一步让你犹豫；你会把结果直接发给对方谈判吗。

## 5. 怎么算指标

| 指标 | 算法 |
|---|---|
| 意见采纳率 | 标"有用"的意见 ÷ 全部高/中意见 |
| 误报反馈率 | 标"不是风险"的意见 ÷ 全部高/中意见 |
| 看不懂比例 | 标"看不懂"的意见 ÷ 全部高/中意见 |
| 漏报 | 用户或法务指出、系统没报的风险条款数；每一例都单独复盘 |
| 省时 | 用户自己看的时间和用工具的时间之比，取中位数 |
| 留存意向 | 回答"会再用"的人数比例 |

前四项由 `uv run cra feedback-report` 直接汇总（也可以访问 `/api/feedback/summary`），只统计高、中等级的意见。

人数少，这些数字只当方向参考，不当结论；每条"不是风险"和"漏报"都要回到原文看原因。

## 6. 试用之后

1. 把每条误报和漏报归类：模型理解错、依据检索不到、公司规范没覆盖、合同类型不在范围内、评测集里没有这种写法。
2. 按出现次数和严重程度排优先级，挑一到两类改。
3. 把真实合同里出现、构造数据里没有的写法补进评测集（打码后），改之前和改之后各跑一次，对比离线数字。
4. 更新 PRD 第 10 节：哪些假设成立、哪些不成立。

## 7. 预算和风险

- 模型花费：10 人、每人 3 份、每份含追问约 $0.05，加上法务对照和重跑评测，总计预计不超过 $10。
- 隐私：只保留打码后的合同和反馈；试用结束后删除原始上传记录。
- 期望管理：反复说明这是试用工具、不构成法律意见，高风险条款仍需法务确认。
