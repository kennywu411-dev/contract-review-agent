# ADR 012：多 Agent 审查（主审 + 三个专职审查员），首轮审查默认改用多 Agent，追问仍用单 Agent

- 状态：已采纳
- 运行（同一金标准，`scripts/compare_models.py` 从 trace 重算）：
  - 单 Agent：`runs/review-full-357021`（S1）、`runs/review-haiku-v2-f434af`（S2，与多 Agent 同一版提示词）
  - 多 Agent：`runs/review-multi-full-f6d836`（M1）、`runs/review-multi-full2-898c71`（M2）
  - 调试：`runs/review-multi-smoke-e95903`（2 份）、`runs/review-multi-s20-0dab26`（20 份）

## 背景

单 Agent 的主要短板是误报：12 份干净合同里有 8–10 份被报出高/中等级意见（ADR 010 已指出这项指标波动大）。想验证"按风险类别拆给专职审查员、各自只看相关条款"能不能减少误报，以及代价是多少。DataPilot 的经验是 Agent 化不一定更好，所以结论按数据定。

## 设计

- 主审（planner）：一次调用，判断我方立场（看不出就反问），把每个条款分派给一个或多个专职组；不审具体条款。
- 三个专职审查员并行（线程池），只拿到分给自己的条款原文、全部条款标题（用来发现缺失条款）和合同首部：
  - 价款与履约：付款、定金、单价、检验期，唯一带查台账工具的组，也可以报"其他"类（如供应商资质过期）；
  - 责任与违约：违约金、免责与责任上限、单方解除；
  - 权利与争议：保密、知识产权、管辖、自动续约。
- 汇总：各组引用编号重编成全局唯一，按（条款, 类型）去重（保留高等级、合并依据），按条款号排序；越界类型丢弃（两次全量都是 0 条）。之后沿用原来的依据校验（ADR 008）。
- 与单 Agent 共用同一段系统提示词（缓存可复用），组别和范围写在用户消息里；检索模型和 DataPilot 连接在线程间共用，调用加锁。
- 调试小样（20 份）里专职审查员把"只约束对方"的违约金和免责当成我方风险（视角错误 2/4）：片段里看不到全局，于是在任务说明里重申"先想清楚这一条约束谁、保护谁"。这两份都在调试小样里，留出集另报。

## 结论与决定

- 多 Agent 的收益集中在"少报不该报的"：干净合同上的误报意见从 13–14 条降到 4–6 条，两次都比单 Agent 两次好，方向在全部和留出集上一致。单 Agent 的误报以"免责/责任"类为主（7 条，多是把数据安全、仓储质量条款当成责任问题）和"其他"类（2–4 条）；多 Agent 里这些条款被分给了别的组、"其他"类也只允许价款组报，这两类误报基本消失。
- 含风险合同上没有明显差别：检出相同；留出集严格精确率 64–67% vs 67–70%，在波动范围内。
- 代价：单份花费约 1.5 倍（仍不到 1 美分）；模型调用约 2.8 倍、模型耗时合计多约 46%，但三个专职审查员并行，挂钟时间持平。
- 决定：Web 首轮整份审查默认用多 Agent（`cra serve --review-mode multi`，可切回 single）；追问只涉及个别条款或换视角重审，仍由单 Agent 带着历史回答。评测命令两种都保留（`cra eval-review [--multi-agent]`）。

## 合并前审查后的加固（问题日志 P24）

- 格式兜底：条款标题识别放宽（"第一条【价款】""第3条：交付"都算）；原文里确有、却没解析出的条款号，或一个条款都识别不出（如"一、价款"编号）时，整份回退单 Agent 审全文，trace 标 `fallback_single`。主审写的"缺失（保密条款）"提示和多写的条号不触发回退，记在 `ignored_assignments`。两次全量里都没有触发回退，上表数字不受影响。
- 单组失败：一个专职组出错（超时、网络），其余组照常汇总，`failed_groups` 记录，总结里注明"该类风险未审"；三组都失败才返回兜底。
- 引用：子 agent 引用了本组没检索过的编号，记入 `invalid_citations`（带组名）再从意见里剔除。
- 并发：检索与查表各一把锁；Web 同一会话的请求串行（并发返回 409）。
- 反问之后：首轮反问、用户补充"我方是甲方"的那一轮才是首次审查，同样走多 Agent，并把用户的补充交给主审。

## 已知风险（评测集测不到）

- 每个条款只有被分到的专职审查员看。风险写在不典型的位置（如在"质量标准"里夹一句免责）时，能否发现取决于主审有没有分派对；评测合同把风险都放在标准位置，这个弱点没被测到。缓解思路：主审可以把一个条款分给多个组（已支持），或加一个"兜底组"扫全文，但会把误报带回来，需要再评。
- 干净合同只有 12 份，单次运行的误报率波动可达十几个百分点；这里用两次 × 两种方式交叉比较才下结论。
