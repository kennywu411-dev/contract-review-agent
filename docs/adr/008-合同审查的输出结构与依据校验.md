# ADR 008：合同审查的输出结构、依据校验（依据不足转人工而不删除）与多轮追问

- 状态：已采纳
- 运行：
  - 审查基线：`runs/review-full-357021`（48 份，Haiku 5.5）；
  - 依据校验与评判：`runs/review-d4-464de8`（复用上面那次的原始意见，Haiku 校验 + Sonnet 5.5 评判）；
  - 多轮追问：`runs/review-dialog-b2b87b`。

## 背景

问答场景（ADR 003、004）的输出是"带引用的句子"，校验后删掉没有依据的句子、全删光就拒答。换成合同审查后，输出单位变成"一条审查意见"，而且两类错误的代价不对称：漏掉一处风险，合同可能就这么签了；多一条待复核的意见，只是法务多看一眼。

## 决定

### 1. 输出结构（`submit_review`，strict schema）

每条意见：条款号、原文摘录、风险类型（10 + 1 类，见 ADR 007，另有 other）、等级（高/中/低）、理由、可直接替换的修改建议、依据编号（检索到的法条/规范 `[C]` 或台账查询 `[T]`）、是否转法务复核。另有 `our_side`（模型判断的我方是甲方还是乙方）和总体结论。

- 只报两类条款：对我方不利且不对等的，违反法律强制性规定或本公司规范的。对等的常规条款、对我方有利的条款不报；"还能写得更完善"的改进点写进总结（问题日志 P19）。
- 判断每一条前先想清楚它约束谁、保护谁（P20 第二轮里模型把"只约束对方"的违约金看反）。
- 看不出我方是甲方还是乙方时反问，不猜。

### 2. 依据校验：两层，依据不足转人工、不删除

- 规则层：从理由和修改建议里抽出"《民法典》第X条""合同编通则解释第X条""本公司规范第X条"这类点名引用，核对它是否真出现在本次检索到的原文里。点名了却没检索到，就是编造或凭记忆错引的直接信号。
- 模型层：Haiku 一次看完本次检索到的全部原文和这份合同的全部意见，逐条判断理由里的规定性说法能否由原文得出（supported / partial / unsupported），并给出真正支撑它的原文编号（可改正挂错的引用）。
- 处理：
  - unsupported、校验器出错、点名了未检索的条文、摘录与合同原文对不上 → 保留意见，标"转法务复核"并写明原因；
  - partial → 理由改写成只保留有依据的部分；
  - 校验器给出的支撑编号与模型引用不同 → 改正引用。

  和问答场景（ADR 004）删句不同，这里一条都不删：删掉一条依据写错、但风险判断本身正确的意见，就等于漏报。

### 3. 多轮追问

追问沿用同一个 agent 和同一段系统提示词（提示缓存不受影响），把上一轮的意见按编号压成结构化历史（`history_from_review`），多给一个终止工具 `answer_followup`。用户补充身份（"我方是甲方"）或要求换视角（"换成乙方视角再看一遍"）时，模型重新调用 `submit_review`。首轮不给 `answer_followup`，避免模型跳过审查直接作答。

## 结果

### 依据校验（42 份有意见的合同，122 条意见；Sonnet 5.5 逐条评判）

| 指标 | 数值 |
|---|---|
| 理由里有无依据说法的意见 | 18.9%（23 条） |
| 其中未被标"转人工"的（会直接误导用户） | 校验前 6.6% → 校验后 0.8% |
| 误拦（有依据却被校验器新标转人工） | 2.0% |
| 点名了但本次没检索到的条文 | 0% |
| 校验器动作 | 新标转人工 2 条，改写理由 42 条，改正引用 95 条 |
| 修改建议质量（Sonnet 1–5 分） | 均分 3.86，≥4 分 77.0%（5 分 15 条、4 分 79 条、3 分 24 条、2 分 4 条） |
| 花费 | 校验 $0.083，评判 $1.55 |

- 原始意见里本来就有不少被模型自己标了转人工（真风险中 47.9%），所以"未拦截"的基数只有 6.6%；校验主要靠"改写成只含有依据的部分"把它降到 0.8%，而不是靠多标转人工（只新增 2 条）。
- 无依据的说法以"误读或扩大适用规范"为主，例如把"公司对外承担责任以合同总额为上限"读成"对方责任也必须封顶"、把存货人的说明义务说成保管人的拒收权；凭空编造条号的情况在这批里没有出现（点名未检索 0%）。
- "改正引用 95 条"多数是把模型引的 3–4 个片段收窄到真正支撑结论的 1–2 个，不全是挂错。

### 多轮追问（26 组，带上一轮审查历史 vs 不带）

| 追问类型 | 带历史 | 不带历史 |
|---|---|---|
| 补充我方身份后完成审查 | 100%（检出 100%） | 100% |
| "你列的第 k 条意见怎么改" | 100% | 0% |
| "第 X 条的依据是什么"（条款对 / 依据对） | 100% / 75% | 62.5% / 50% |
| 换对方视角重审（原风险条款仍被报出） | 100%（13.9%） | 100%（8.3%） |

"第 k 条"这类指向上一轮输出的追问完全依赖历史；按条款号、按身份的追问合同正文里就有线索，不带历史也能答。结构化历史（编号的意见列表）很短，不需要 ADR 005 那样的摘要压缩。

## 代价

- 依据不足的意见不删，法务要看的条数会多；用"转人工复核"的标记和原因让他们优先看这些。
- 校验多一次 Haiku 调用：每份合同约 $0.002、数秒。
- 评判员是 Sonnet，存在 LLM 评判的随机性（问题日志 P17），这里只比较同一次评判里的前后数字。
