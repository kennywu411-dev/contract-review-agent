# ADR 013：难评测集 v2，长合同、5 类难度的风险、带干扰项的干净合同；多 Agent 改进轮把检出补到 100%

- 状态：已采纳
- 评测集：`evals/contracts_v2.jsonl`（`scripts/make_contracts_v2.py` 生成，固定种子，全部构造数据），抽查清单 `evals/contracts_v2_spotcheck.md`
- 运行（同一份标准答案，`scripts/compare_v2.py` 从 trace 重算）：
  - 单 Agent：`runs/review-v2-single-full1-2dc892`（S1）、`runs/review-v2-single-full2-d2a43e`（S2）
  - 多 Agent（ADR 012 原版）：`runs/review-v2-multi-full1-62b87d`（M1）、`runs/review-v2-multi-full2-00251b`（M2）
  - 多 Agent 改进后：`runs/review-v2-multi-improved1-27de2d`（I1）、`runs/review-v2-multi-improved2-6e7b9b`（I2）
  - 小样：`runs/review-v2-single-s10-a00f54`、`runs/review-v2-multi-s10-9dd601`（各 10 份）

## 背景

v1 的 48 份合同里，73 处风险全部写在标准位置，用的是典型说法，单 Agent 和多 Agent 检出率都是 100%，区分不出能力，只能比误报（ADR 010、012）。真实合同的难点在于：风险藏在标题不相关的条款里；措辞换了说法；要两条合起来看才有问题；数值只越过红线一点点。干净合同里也有很多看起来像风险、其实合规的写法。

## 评测集设计

- 60 份长合同（每份 25–30 条）：在 v1 的 17 个标准条款之外，补上定义、价格调整、包装、运输、所有权、质保、发票、履约保证、人员、个人信息、知识产权担保、变更、转让、廉洁、联系人、权利保留、完整协议等真实合同常见条款。条款数随机取 25–30，平均约 2200 字（v1 约 1000 字）。
- 30 份植入风险，共 75 处，分 5 类：
  - 隐蔽位置 18：风险句夹在非标准条款里，对应的标准条款是安全写法。例如发票条款里的单方违约金、变更条款里的任意解除权、"完整协议"条款改写管辖并声明优先。
  - 换说法 18：位置标准，但不用触发词。例如"补偿相当于合同金额千分之三十的款项"、"自对方书面告知之日起不再继续履行"、"效力延续至下一合同年度"。
  - 跨条款组合 12（标准答案记多条）：
    - 付款以收到发票为前提，开票又以收到付款为前提；
    - 定义把"违约方"限定为只有甲方的义务；
    - 检验期从首批起算，而交付允许分批 90 日；
    - 管辖写"合同签订地"，首部签订地点却在对方城市。
  - 临界值 15：数值刚越过租户规范或法律的红线，例如定金 22%、检验期 12 日（华信要求 15 日）、续期涨幅 8%（云启要求 5%）。单价超出复核线，按全部历史均价和近十二个月均价两种算法都成立。
  - 标准位置对照 12：v1 的写法。
- 30 份干净合同，带 67 个干扰项：
  - 刚好合规的数值 25 个；
  - 合法免责 15 个（不可抗力、甲方原因不属质保范围）；
  - 对我方有利的单方条款 19 个；
  - "签订地法院管辖 + 签订地在我方"8 个。
- 标准答案：每处风险记条款号（组合风险记多条）、类别、风险类型（可接受的近义类型 `alt_types`）、等级、受损方、理由（`why`）、合法依据。台账里对方资质已过期或会在履行期内到期的、对等性规范要求等，记为"报出也对"（acceptable）。
- 评分扩展：
  - 组合风险落在任一相关条款上都算检出；
  - 新增按类别统计的检出率；
  - 统计每类干扰项被报出高/中等级意见的比例；
  - `cra eval-review --evalset v2`，`--resume` 支持中途续跑。

## 质检

- 生成后先以法务视角逐份通读 60 份合同。它发现：
  - 资质"将在履行期内到期"没有计入合理意见；
  - 解除权模板在我方为甲方时文义颠倒；
  - 设备类检验期的起算点不对；
  - 两处组合风险单看已经构成风险。
- 以上都在生成器里改掉了，标准位置的理由也改成写这份合同的具体事实。
- 修复时还发现生成结果随哈希种子变化（遍历集合），改为排序后可复现。
- 抽查清单 20 条经用户审核通过后才开始付费评测。

## 漏检分析

- 单 Agent：两次共漏 5 处。
  - 组合 3 处：保密信息被定义限定为甲方信息 ×2，付款与开票互为前提 ×1；
  - 隐蔽位置 1 处：完整协议条款改写管辖；
  - 临界值 1 处：首付款 20%，云启要求 30%。
- 原版多 Agent：两次各漏 8–9 处，原因有三：
  - 定义条款没人看：主审一次都没把"第一条 定义"分派出去，所以凡是需要结合定义才看得出的组合风险全部漏掉（知识产权、保密、违约方定义）。
  - 相关条款分到了不同组：定金条款给了价款组，违约金条款给了责任组，两组都看不到"叠加适用"。还有一份合同的保密条款主审根本没分派。
  - 专职组不比对红线：临界值条款分对了组，但保密期 2 年（要求 3 年）、违约金日万分之八（要求万分之五）、首付款 20%（要求 30%）都没拿去对照规范。单 Agent 看全文时会去检索规范。

## 改进轮（一轮，低成本）

改动范围（TDD，`tests/test_multi_agent.py` 新增 3 个测试）：

1. 定义条款自动发给每个分到条款的组；
2. 主审没分派的条款，按关键词兜底分组（付款/定金/发票 → 价款组，违约/赔偿/解除 → 责任组，保密/知识产权/管辖/续期 → 权利组），trace 里记 `auto_assigned`；
3. 主审提示词："每个条款都要分派，不要只看标题；同时涉及几类风险就分给几个组"；
4. 专职组提示词："比例、天数、年限、金额都要检索本公司规范逐项对照红线；结合定义条款和其他条款看"。

结果：两次都是 75/75 全部检出。代价有三：

- 风险合同上的高/中误报从 13–16 条增加到 27–30 条；
- 干净合同误报 53% → 77–83%，回到和单 Agent 相近的水平；
- 严格精确率 53% → 33%：几个组都拿到了定义条款，会从不同类型角度报同一处风险，按"条款 + 类型"去重时合并不掉。
- 单份花费约为原版的 1.75 倍（$0.0067 → $0.0118），是单 Agent 的约 2.5 倍，但仍不到 2 美分。

改进是根据全部 60 份上的漏检原因设计的，没有按开发集、留出集分开调参。只改了一轮，没有拿结果反复迭代。

## 决定

- Web 首轮审查默认用改进后的多 Agent。 合同审查里漏掉一处风险的代价，比多看几条误报大得多。改进后它是唯一两次都 100% 检出的方案；精确率（高/中）62.6–65.7%，仍不低于单 Agent 的 61.0–61.6%。
- 误报回升是已知的下一步工作：
  - 同一处风险被几个组从不同类型角度重复报出，可以在汇总时按"条款相同、理由相近"再合并；
  - "刚好合规"的数值仍有 20–28% 被报出，可以要求专职组在理由里写出规范红线的数值，再做规则核对。
- 单 Agent 保留（`cra serve --review-mode single`），用作对照和低成本模式。

## 已知局限

- 评测集由同一个生成器构造，风险句式是有限的模板（隐蔽 11 种、换说法 14 种、组合 12 种），会被"学会"。改进轮只改了通用的分派和比对规则，没有针对具体句式写提示。
- 标准答案在跑完之后修正过一次（P25）：数据集本身的基础定义、安装调试起算点和"对我方有利"的自动续期条款，引出了合理意见。合同正文没改，6 次运行用同一份新答案重算，修正前后的数字都已登记。
- 干净合同 30 份：同一方案两次运行的干净合同误报率可以差 20 个百分点（S1 90% / S2 70%），比较时要看两次的区间。
