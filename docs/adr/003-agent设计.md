# ADR 003：手写工具循环 + 4 个工具 + 结构化作答，默认 Haiku 5.5（effort=low）

- 状态：已采纳
- 运行：`runs/agent-full-ad8ba4`（174 题全量）、`runs/agent-s20-cb1327`（20 题小样本）

## 决定

1. 手写工具循环，不用 SDK 的 tool runner。理由：
   - 要逐步记录 token、花费、耗时和工具的输入输出，阶段 5 的 trace 回放靠它；
   - 最多 6 步；步数用完、或模型没调用终止工具就结束时，统一记为 fallback。
2. 4 个工具：
   - `search_docs{query}`：检索文档；
   - `run_sql{sql}`：走 DataPilot 的只读 MCP 查表；
   - `ask_clarification`：反问，终止工具；
   - `final_answer{refuse, refuse_reason, sentences[{text, citations}]}`：作答，终止工具。

   所有工具都开 `strict: true`。Haiku 5.5 不支持强制 tool_choice，所以终止靠提示词约束，再加上 fallback 兜底。
3. 安全边界放在代码里，不放在提示词里：
   - 检索的学校范围由会话注入，工具参数里没有 school；
   - 查表结果里带 school 列的行，只保留本校和国家层面。
4. 结构化逐句引用：引用编号 C1… 和 T1… 在同一会话内全局递增。模型写成 `[C1]`、`C1、T2` 时统一规整；引用了不存在的编号就记入 `invalid_citations`，阶段 4 再做降级处理。
5. DataPilot 接入：在 DataPilot 的 `data/dev_databases/campus` 下建软链接，指向本仓库的 `data/campus`，不改 DataPilot 的代码。本机找不到 DataPilot 时，退回本地只读 sqlite（`mode=ro` + 单条 SELECT + 授权回调）。
6. 模型与缓存：
   - 模型用 `claude-haiku-5-5`，`effort=low`，thinking 用默认的 adaptive；
   - system 按学校生成、内容稳定，带 `cache_control`；
   - 请求顶层也带 `cache_control`，自动缓存消息前缀。

## 严格口径下"失败"的分类（修复前那一轮）

- 该拒答却作答的 6 题：
  - 4 题是主观题（"难不难""哪个影响大"）或文件里没有的数据。agent 的回答是：先声明无法评价主观部分，再给出客观规定，并全部带出处（例如 bnu-039）。
  - 2 题（njust-011 研究生学业奖学金、upc-042 保研是否只看必修课）：先说明本校文件没有相关规定，再给出国家层面的标准。
  - 这些都属于"部分拒答"：声明了不能回答的部分，同时补充了有出处的内容，算不上幻觉。评测集里有几题的标准答案本身也写着"可补充……"。
- 该反问却作答的 4 题：agent 没有反问，而是把各种情况分别讲清楚（例如"休学最多几年"：普通休学、休学创业、参军入伍分别回答）。
- 严格口径的问题：作答、拒答、反问三分太粗。阶段 4 要加"部分拒答"这一类，并用 LLM 评判来判断"不能回答的部分有没有明确声明"和"每句话有没有原文支撑"。到那时，拒答正确率按这个口径重新计算；严格口径同时保留。

## 延迟目标校准

PRD 暂定 P50 ≤ 6s、P95 ≤ 15s，并注明"阶段 3 后校准"。实测 P50 是 8.1s：两次模型调用约 6s，检索约 2.3s，6s 的目标不现实。校准为 P50 ≤ 10s、P95 ≤ 15s，实测两项都达标。之后可以从这几处继续降：
- 检索不做重排，走 ADR 002 的降级方案，每题省约 2s；
- 前端流式输出，降低感知延迟；
- 单步答完时省掉第二次调用。

## 成本观察

缓存写入占输入 token 的 47%。原因是请求顶层的 `cache_control` 每一步都把整个消息前缀写进缓存，而一题平均只有 2.3 步，写进去的前缀很少被再次读到。阶段 5 做成本面板时对比"只缓存 system"的方案：缓存写的价格是普通输入的 1.25 倍，缓存读只要 0.1 倍。
