# ADR 007：场景从"高校规章问答"改为"合同风险审查"，项目改名 Contract Risk Review Agent（合同风险审查智能体）

- 状态：已采纳

## 背景

阶段 0–4 用高校规章问答把整条链路做通并做了评测：解析入库、混合检索与重排、agent 多工具路由、逐句引用、生成后校验、trace、Web 界面。问题出在求职层面："知识库问答 / 文档助手"已经是最常见的题目，辨识度很低。用户决定换成一听就懂、所有公司都有的业务："审核"合同，而不是"问答"规章。

## 决定

1. 场景：输入一份商业合同（采购、销售、委托、承揽、数据处理等），agent 逐条找出对我方不利的条款，给出风险类型、风险等级、修改建议，以及依据原文（《民法典》合同编、合同编通则解释、《民事诉讼法》、官方合同示范文本、租户内部审批规范）。
   - 拿不准的条款转法务人工复核，对应原来的"拒答"；
   - 材料不全时先反问，比如"我方是甲方还是乙方"，对应原来的"反问"。
2. 风险类型（10 + 1 类），经调研确定：
   - 违约金过高或只约束一方；
   - 免责条款、责任无上限；
   - 单方解除权；
   - 检验期过短、逾期视为合格；
   - 付款周期过长、背靠背付款；
   - 保密条款缺失或不对等；
   - 知识产权归属不利；
   - 管辖不利、或裁或诉；
   - 自动续约；
   - 定金超过 20%；
   - 外加一类：单价明显高于供应商台账里的历史价（通过 DataPilot 只读 MCP 查表）。
3. 复用关系：

   | 原能力 | 在合同场景里的用法 |
   |---|---|
   | 解析（页码、条款号、标题链） | 合同和法条都按"第 X 条"切分 |
   | 混合检索 + 重排 | 检索法条、示范文本、租户规范 |
   | 学校隔离 | 换成租户隔离：不同公司的审批规范互相不可见 |
   | DataPilot 查表 | 换成查供应商台账 |
   | 逐句引用 + 生成后校验（ADR 004） | 每条审查意见的依据要能在法条原文里找到，防止编造法条 |
   | trace、多轮记忆、Web 界面 | 原样复用；高亮的对象从 PDF 原文换成合同里的风险条款 |

4. 改名：英文名 Contract Risk Review Agent，中文名合同风险审查智能体；Python 包 `contract_review`，命令行 `cra`。
5. 高校场景的成果：阶段 2 检索、阶段 3 agent、阶段 4 校验 v1/v2、多轮记忆初步结果，作为方法验证保留在 `docs/numbers.md` 和 ADR 002–005，不再新增付费评测。

## 数据与许可（详见 `docs/合同场景调研.md`）

- 法条：《民法典》、合同编通则解释、《民事诉讼法》。依据《著作权法》第五条，法律、法规和司法解释正文不受著作权保护，可以入库引用。
- 示范文本：来自市场监管总局合同示范文本库，网站只写了"版权所有"，没有开放许可。因此原文只在本地使用，不进 git、不对外分发，仓库里只保存文本 id、下载脚本和植入规则。
- 构造数据，文档里一律标明"构造"：
  - 评测合同：条款顺序参照 7 份示范文本，条款正文全部自写（原计划"填示范文本"，实施时改为自写：示范文本无开放许可，复制正文的合同不能入 git；自写后评测集可以公开复现），填入虚构的当事人和价格，再按规则植入风险条款；
  - 3 个租户的内部审批规范；
  - 供应商台账。

## 评测

- 构造 48 份合同：36 份含风险（每份 1–3 处，共约 70 处，每类至少 6 处），12 份干净。甲方、乙方视角各占一半；另有 4 份不告诉"我方是谁"（测反问），6 处临界条款（测转人工）。
- 自动判分的指标：风险检出率（召回）、误报率（按条款、按份）、风险类型判对率、依据引用准确率（引用的条号是否在该风险的合法依据集合里，并且确实存在）、转人工率、反问率、单份合同的花费和耗时，以及 阶段 4 校验前后的"编造或错引法条"比例。
- 修改建议的质量抽 20 份，用 Sonnet 评。

## 代价

- 高校场景评测集上积累的数字（Recall@5 97.9% 等）不能直接写成合同场景的效果，对外报告时要分开写。
- 构造数据存在"自己出题自己考"的风险。缓解办法：植入句式每类准备多种写法；评测时 agent 看不到植入规则；保留干净合同测误报。
