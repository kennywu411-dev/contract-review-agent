# ADR 005：会话记忆用"槽位 + 最近几轮原文 + 早期摘要"，超出预算时用 Haiku 压缩

- 状态：已采纳
- 运行：见文末"结果"

## 背景

学生会连着追问："北师大国奖多少钱 → 那研究生呢 → 需要什么条件"。之前每题独立作答，第二问单独看根本没法回答。

## 比较过的方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 滑动窗口 | 只带最近 N 轮原文 | 简单，不丢细节 | 第 N+1 轮以前的身份信息（"我是大二"）会被挤掉；历史越长，token 线性增长 |
| 全量摘要 | 每轮都把历史压成摘要 | token 最少 | 每轮多一次模型调用；摘要会丢掉数字和出处，"那研究生呢"指的是哪个奖项也可能丢 |
| 纯槽位 | 只记学历层次、年级、专业等 | 最省 | 理解不了"它""这个"这种指向上一轮内容的指代 |
| 槽位 + 最近 K 轮原文 + 早期摘要（选用） | 槽位一直保留；最近 K 轮保留原文；估算超出预算才把更早的轮次压成摘要 | 指代靠最近原文，身份靠槽位，长对话靠摘要兜底；没超预算时不多调模型 | 实现复杂一些；压缩那一轮多一次 Haiku 调用 |

## 决定

1. 槽位：学历层次、年级、专业，用规则从学生的问题里抽取（`memory.extract_slots`），新值覆盖旧值，永远不参与压缩。学校由会话决定，不进槽位；切换学校就开新会话，避免把 A 校的上下文带到 B 校。
2. 每轮记什么：校验后保留的句子，加上可读的出处（"《文件名》第 12 页"）。不记 C1、T1 这类编号，因为编号每轮都会重新开始，不能跨轮引用。
3. 怎么用：把历史拼成 `<对话历史>` 放在当前问题前面。提示词要求：追问时先用历史补全指代，再检索；换了话题就不要被历史带偏；作答必须重新检索，引用本轮的编号。
4. 压缩：用"中文每字约 1 token"粗略估算长度，超过预算（线上 1200，评测时故意设成 300）就把最近 `keep_last` 轮以外的内容交给 Haiku，压成 200 字以内的摘要，要求保留身份、数字、出处和没解决的问题。压缩失败时只保留最近几轮，不能让历史无限增长。
5. Web：每段对话一个会话 id，服务端按 id 保存记忆（单机内存，最多 200 个会话）；有"新对话"按钮；切换学校自动开新对话。

## 评测设计

- 数据：`evals/dialogs.jsonl`，25 组对话、74 轮，其中 49 个追问轮。按追问类型分：
  - 指代 7 组；
  - 省略 7 组；
  - 槽位延续 6 组；
  - 换话题 5 组。

  追问轮的问题单独看都答不了或会答错。标准出处按单轮评测的同一套规则用 SQL 查原文。
- 对比的三种方式：
  - none：不带记忆；
  - full：完整历史；
  - compress：预算 300，只保留最近 1 轮原文，其余压缩。
- 追问正确：
  - 可回答或需查表的轮次：Sonnet 评判答案要点正确，并且引用命中标准出处；
  - 应拒答的轮次：拒答，或者明确声明了边界。

  评判时把对话上文一并交给 Sonnet。
- 同时记录：历史长度、每轮输入 token、压缩次数、作答花费。

## 结果

高校场景下跑了 10 组对话后，停止（项目换为合同风险审查，ADR 007）。初步结果（`runs/dialog-full-c3184d`，每种方式 18 个追问轮）：不带记忆 6/18、完整历史 10/18、历史加压缩 12/18。样本太小，只能说明"有记忆明显好于没有"；压缩比完整历史更好，可能只是噪声。合同场景下会用新的多轮子集重新评测。
