# ADR 011：合同审查的长对话上下文压缩，结构化摘要 + 规则核对；产品默认预算放宽到 8000 字

- 状态：已采纳
- 运行：
  - 最终代码重跑：`runs/review-longdialog-v2-d0b2fa`（审查加固之后，下表以它为准）
  - 第一次全量：`runs/review-longdialog-full-1d77c3`（12 组 × 8 轮 × 3 种方式；判分规则修正后用 `scripts/rescore_longdialog.py` 从 trace 重算，原始汇总在 `summary_original.json`）
  - 小样：`runs/review-longdialog-s3-235a43`（3 组）；第一次小样已中止，不计入结果
- 第 0 轮复用 `runs/review-haiku-v2-f434af` 的审查结果。

## 背景

ADR 008 的多轮追问只带"上一轮审查"。真实使用中，一份合同会连续追问很多轮：问依据、换视角重审、换回来、告诉系统"这条已和对方谈妥"……后面的问题会回指最早的审查（"最开始你列的第 1 条"）和中途的决定。历史越来越长，需要压缩；高校阶段 ADR 005 和 `memory.py` 有过"最近几轮原文 + 较早摘要"的半成品，这里复用它的结构并按合同场景改造。

## 决定

`review_memory.ReviewMemory`，三种方式：

- full：全部轮次原文；
- window：只留最近 2 轮原文；
- compress：历史超过预算时，最近 2 轮保留原文，更早的轮次交给 Haiku 压成结构化摘要（JSON：我方立场、意见台账"第几轮第几条：条款号 + 状态"、用户确认/否定的结论、已引用依据），多次压缩时在已有摘要上合并。
- 规则核对：被压缩轮次里的每条意见（轮次 + 序号）都必须出现在台账里，缺了按规则补录；摘要模型出错或输出被截断时，整份台账用规则生成，不会丢掉早期意见。
- 每轮带绝对轮次号（第0轮是首次审查），系统提示词说明"最开始列的第 k 条 = 第0轮第 k 条""已谈妥的意见之后不再列"。
- Web 会话改用这个记忆（`/api/review`），产品默认 compress、预算 8000 字。

## 评测

12 组长对话（留出集合同、首次审查至少 3 条带条款号的意见），每组 8 轮追问：第 1–3 轮问近期意见、依据和一个无风险条款；第 4 轮告诉系统"第 2 条意见已谈妥"（不计分）；第 5、6 轮换对方视角再换回；第 7 轮问"最开始列的第 1 条是哪一条"，第 8 轮问"最开始的意见里除谈妥那条外还有哪些要改"（第 7、8 轮回指早期轮次）。全部自动判分。为了让压缩真正发生，评测用 3000 字预算。

## 结论

- 只留最近几轮不可行：凡是回指早期轮次的问题全错，追问正确率掉到 71%。
- 摘要压缩不损失正确率：最终代码下与全量历史完全持平（98.8%，回指早期轮次 95.8%），历史缩短 32%，后两轮输入 token 降 17%。
- 省钱很有限：第一次全量里压缩每轮都触发，摘要花费反而让总成本高 12%；改成成批压缩后总花费比全量低 1%。原因是每轮输入的大头是系统提示、合同全文和检索结果（约 1.5 万 token），历史只占一小部分。压缩的价值在更长的会话（几十轮、或合同和历史接近上下文上限）里才会明显，这里没有测。
- 决定：保留摘要压缩作为长会话的兜底，产品默认预算 8000 字（这批 8 轮对话不会触发），只有真正长的会话才压缩。

## 合并前审查后的加固（问题日志 P24）

- 规则补录沿用上一份摘要里的状态（"已谈妥"不会因为模型第二次漏掉而退化成"已报"）；同一条意见的补录只计一次。
- 成批压缩：最近 2 轮之外至少攒满 2 轮才压一次，超预算后不再每轮都调摘要模型。
- 不给摘要模型时按纯规则台账处理，不算错误；摘要头部的"我方"取全部轮次里最新的立场。
- "首次审查"标在第一次给出意见的轮次（先反问时不是第0轮），系统提示同步。
- 判分收紧：书名号法条引用和意见编号先剔除；"排除语境"不能跨过别的条款、须以明确的排除词收尾。
- 以上改动后用最终代码重跑全量（见下方"最终代码重跑"）。

## 实施中踩到的坑（问题日志 P23）

- 第一次小样里压缩根本没触发（8 轮全量历史只有约 5600 字，预算设成了 6000），三种方式实际上只是两种。
- 摘要输出被截断：Haiku 自适应思考的 token 也算在 `max_tokens` 里，1500 不够，8 次里 4 次 JSON 不完整。上限改为 4000，并对 `stop_reason == max_tokens` 明确报错。
- 判分规则两处错误（同一条款上有多条意见时的标准答案；把"第0轮第1条"这类意见编号当成合同条款），修正后从 trace 重算，改判 12 轮，全部由错改对。
